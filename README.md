# 🪐 Agent Orchestra

Веб-дашборд, где **оркестратор** и **4 ИИ-агента** (OpenAI, Groq, Anthropic, Gemini) вместе делают проект по вашему запросу
(«создай шопинг-сайт») и в конце отдают **ZIP**. Всё происходит в космосе: агенты — планеты вокруг ядра-оркестратора,
задачи летят между ними кометами.

## Быстрый старт

Нужны **Python 3.10+** и **Node.js 18+**. Ключи уже лежат в `.env` в корне (см. `.env.example`).

```bash
python run.py          # установит зависимости, запустит бэкенд (:8000) и фронтенд (:5173), откроет браузер
```

Windows: двойной клик по `start.bat`. Linux/macOS: `./start.sh`.

| Команда | Что делает |
|---|---|
| `python run.py` | dev-режим: FastAPI `:8000` + Vite `:5173` |
| `python run.py --prod` | собирает фронтенд, всё отдаёт бэкенд на `http://localhost:8000` |
| `python run.py --demo` | имитация провайдеров — посмотреть анимации без ключей |

Вручную:
```bash
pip install -r backend/requirements.txt
cd backend && python -m uvicorn app.main:app --port 8000      # терминал 1
cd frontend && npm install && npm run dev                      # терминал 2 → http://localhost:5173
```

## Ключи и модели

* Имена переменных в `.env`: `OPENAI_API_KEY`, `GROQ_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY` (для Gemini подойдёт и `GOOGLE_API_KEY`).
  Подхватываются и похожие имена (любая переменная с `KEY`/`TOKEN` и названием провайдера).
* В ⚙ **Настройки** у каждого агента: выпадающий список моделей (**запрашивается у API провайдера**, в коде не зашит) и поле ключа.
  Ключ из UI живёт только в памяти сервера. Модель оркестратора выбирается там же.
* Провайдер без ключа показывается тусклым («нет ключа») и в работе не участвует. Достаточно одного ключа.

## Как это работает

0. **Разговор или работа?** Оркестратор первым же вызовом решает, чего хочет пользователь. Приветствие, вопрос, small talk или слишком расплывчатый запрос —
   он отвечает сам (пузырь «Центр управления» на сцене), агентов не запускает и ZIP не делает. Если нужно что-то создать — начинает миссию.
   Он же определяет **язык запроса**, и весь текст для людей (названия задач, README, комментарии, ответы) пишется на этом языке.
   Последние реплики диалога передаются оркестратору, поэтому уточнения вроде «сделай то же на React» работают. Подписи самого интерфейса остаются русскими.
   **Память.** Кнопка 📖 в шапке открывает «Память миссий»: заметки о вас (оркестратор добавляет их сам, когда вы пишете «запомни, что…» или сообщаете постоянные
   предпочтения; можно добавить вручную) и история созданных проектов (пишется после каждой миссии). Память подмешивается в промпты оркестратора при анализе запроса и планировании.
   Хранится локально в `backend/data/memory.json` (в `.gitignore`). Консоль: `memory`, `remember <текст>`, `forget <id|all>`. API: `GET/POST/DELETE /api/memory`.
1. **Контракт.** Оркестратор фиксирует стек, структуру файлов, точные имена функций/id/роутов и стили — общий источник истины.
2. **План.** Разбивает работу на задачи по 1–3 файла, назначает агентов по «характеру» (Groq — быстрые простые файлы, Anthropic — сложная логика,
   OpenAI — бэкенд/структуры, Gemini — разметка/доки), задаёт зависимости. Циклы автоматически разрываются, непокрытые файлы докидываются.
3. **Выполнение.** Независимые задачи идут **параллельно**; результат (файлы) задачи-зависимости передаётся следующему агенту как контекст.
4. **Надёжность.** Единый интерфейс-адаптер для провайдеров; при `429`/`5xx` — повторы с экспоненциальной задержкой (учитывается `Retry-After`
   и подсказки «try again in…»); если агент не справился — задача **переходит к другому агенту** (failover). По умолчанию 1 задача на провайдера
   одновременно (`CONCURRENCY_<PROVIDER>` в `.env`) — бережёт лимиты бесплатных ключей Gemini/Groq.
   **Инструменты агентов.** Протокол провайдер-независимый (текстовые блоки), поэтому работает у всех четырёх моделей одинаково. Агент может вызвать
   `list_files`, `read_file`, `search_code`, `get_contract` (до 3 раундов по 3 вызова), а после ответа система сама запускает `lint`
   (JSON, Python, JS через `node --check`, баланс CSS, ссылки в HTML, заглушки вида «остальной код…») и возвращает ошибки на самоисправление.
   Оркестратор перед ревью тоже прогоняет линтер по всему проекту. В интерфейсе у каждой планеты 5 спутников-инструментов; при вызове между
   планетой и спутником летит пакет по кривой туда и обратно (зелёный — успех, красный — ошибка), всплывает плашка с аргументом, растёт счётчик.
   Команда консоли `tools` показывает счётчики и последние вызовы.
5. **Ревью.** Оркестратор сверяет файлы разных авторов и при несостыковках запускает задачи-правки.
6. **ZIP.** Файлы пакуются, появляется карточка «Миссия выполнена → Скачать ZIP».

## Интерфейс

* Фон: туманности, звёзды с параллаксом (двигайте мышью), редкие кометы. `prefers-reduced-motion` отключает движение.
* Статусы планет: ожидает · думает (аура + бегущие частицы) · пишет (искры) · готово (галочка-пружина) · ошибка (красное мерцание).
* Справа: «бортовой компьютер» с печатающимся потоком выбранного агента (клик по планете или вкладке) и дерево файлов (клик по файлу — просмотр).
* Снизу: маршрут миссии — станции, волны параллельных задач, прогресс-бары.
* **Светлая и тёмная тема** — переключатель ☀/🌙 в шапке (запоминается в браузере; также команда `theme light|dark`).
* **Бортовой компьютер интерактивен:** вкладка «Консоль» с командами (`help`, `status`, `agents`, `tasks`, `files`, `cat <файл>`, `open <файл>`,
  `focus <агент>`, `contract`, `review`, `logs`, `run <запрос>`, `cancel`, `clear`), история ↑/↓, автодополнение Tab, кликабельные имена файлов,
  кнопки «следовать / копировать / очистить / на весь экран», режим «авто» (поток сам переключается на активного агента).
* Пока агент работает над задачей, его планета получает HUD-кольца, сканирующий луч, спутник-носитель задачи и плашку с названием задачи.
* Страница переживает перезагрузку: события миссии воспроизводятся с сервера.

## Структура

```
backend/app/   config.py (ключи, настройки) · providers.py (адаптеры, ретраи, демо)
               tools.py (инструменты, линтер) · memory.py (память) · prompts.py · orchestrator.py (контракт→план→задачи→ревью→ZIP) · main.py (REST + WebSocket)
frontend/src/  engine.js (орбиты, корабли-кометы, частицы, сверхновая) · components/ · useOrchestra.js
run.py         единая команда запуска
```

API: `GET/POST /api/settings`, `POST /api/runs`, `WS /ws/runs/{id}`, `GET /api/runs/{id}/download`.

## Заметки

* Бесплатные лимиты: крупные проекты на Groq/Gemini могут упираться в токены в минуту — это нормально, сработают повторы и failover.
  Для надёжности выберите оркестратором самую сильную модель (Anthropic/OpenAI).
* Результаты запусков лежат в `backend/runs/`. `.env` не коммитьте (он в `.gitignore`).
